# Security policy

## Supported versions

Before the first public release, only the current default branch is maintained.
Published support ranges must be added here when versioned releases begin.

## Report a vulnerability

Use the repository host's private vulnerability-reporting or security-advisory
feature. Do not disclose a suspected vulnerability, exploit, credential,
personal record or private infrastructure detail in a public issue.

Include the affected revision, impacted contract or component, reproduction
conditions, likely impact and any suggested mitigation. Use synthetic or
redacted evidence. The maintainer should acknowledge the report, establish a
private coordination channel, assess affected versions and agree on disclosure
timing with the reporter.

If private reporting is unavailable, open a public issue containing only a
request for a private security contact and no vulnerability details.

## Scope

The kit contains specifications, schemas, synthetic fixtures and offline
validators. Its checks do not prove the security of a platform built from it.
Report defects in those artifacts here. Report vulnerabilities in a downstream
runtime to that runtime's maintainer.
