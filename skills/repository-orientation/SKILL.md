# Repository orientation

Build a small operating map: task objective, governing instructions, relevant
source locations, declared environment, current changes and completion checks.

Read applicable repository instructions and inspect status plus focused diffs.
Keep pre-existing changes distinct from the work requested. Search filenames and
symbols before loading broad documentation; inspect decision-critical source.

For a status or audit request, map each selected requirement to source, tests,
build or live evidence. Plans and completion notes are leads, not implementation
proof. Distinguish implemented, partial, documentation-only and unavailable
evidence. A stale index or zero search results do not establish absence.

Inspect manifests and supported commands without executing environment loaders.
Use the host's available authorized file/search/execution capabilities; direct
local tools are sufficient when permitted. Do not require a named broker,
index service, private catalog or home-directory layout.

Return only the map needed for the current task and any consequential ambiguity.
